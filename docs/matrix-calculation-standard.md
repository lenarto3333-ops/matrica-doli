## 4. Вхідні дані

Обов’язковий числовий вхід:

```text
DD.MM.YYYY
```

Вимоги:

- дата повинна існувати в календарі;
- день — від 1 до 31 з урахуванням конкретного місяця;
- місяць — від 1 до 12;
- рік — від 1900 до поточного року;
- початкові нулі не впливають на результат;
- стать не передається у функцію числового розрахунку.

## 5. Правило редукції

Позначення `R(X)` означає приведення числа до діапазону 1–22 шляхом повторного складання його десяткових цифр.

```text
R(X) = X, якщо 1 ≤ X ≤ 22
R(X) = R(сума цифр X), якщо X > 22
R(0) = 22
```

Редукція не є операцією `X mod 22`.

Приклади:

| Значення | Обчислення | Результат |
| ---: | :--- | ---: |
| 22 | без змін | 22 |
| 24 | `2 + 4` | 6 |
| 29 | `2 + 9` | 11 |
| 50 | `5 + 0` | 5 |
| 1973 | `1 + 9 + 7 + 3` | 20 |

## 7. Обов’язковий порядок розрахунку

### 7.1. Основні точки

```text
a = R(DD)
b = R(MM)
c = R(сума цифр YYYY)
d = R(a + b + c)
e = R(a + b + c + d)
```

### 7.2. Кути родового квадрата

```text
f = R(a + b)
g = R(b + c)
y = R(c + d)
k = R(d + a)
```

### 7.3. Основні осі

Для кожної основної точки `P` з множини `{a, b, c, d}`:

```text
p1 = R(e + P)
p2 = R(P + p1)
p3 = R(e + p1)
```

У програмній структурі вісь зберігається як:

```text
[p2, p1, p3]
```

Відповідні поля: `dayAxis`, `monthAxis`, `yearAxis`, `karmaAxis`.

### 7.4. Сила роду

Сила роду обчислюється лише після визначення всіх чотирьох кутів:

```text
q = R(f + g + y + k)
```

Центральна точка `e` у цій формулі не використовується.

### 7.5. Внутрішні точки родових програм

Для кожного кута `C` з множини `{f, g, y, k}`:

```text
inner(C) = R(C + q)
outer(C) = R(C + inner(C))
```

Порядок пари у програмному інтерфейсі — від центра до кута:

```text
[inner, outer]
```

Відповідність:

| Поле | Кут | Формула |
| :--- | :---: | :--- |
| `nwAxis` | `f` | `[R(f + q), R(f + R(f + q))]` |
| `neAxis` | `g` | `[R(g + q), R(g + R(g + q))]` |
| `seAxis` | `y` | `[R(y + q), R(y + R(y + q))]` |
| `swAxis` | `k` | `[R(k + q), R(k + R(k + q))]` |

### 7.6. Особисте та соціальне призначення

```text
sky = R(b + d)
earth = R(a + c)
personalTotal = R(sky + earth)

maleLine = R(f + y)
femaleLine = R(g + k)
socialTotal = R(maleLine + femaleLine)

spiritualTotal = R(personalTotal + socialTotal)
planetaryTotal = R(socialTotal + spiritualTotal)
```

### 7.7. Кармічний хвіст і канали

```text
moneyEntrance = yearAxis[1]
loveEntrance = karmaAxis[1]

x = R(loveEntrance + moneyEntrance)
moneyEnergy = R(x + moneyEntrance)
loveEnergy = R(x + loveEntrance)

karmicTailThird = R(d + loveEntrance)
karmicTail = [d, loveEntrance, karmicTailThird]
```

Канал стосунків:

```text
[loveEntrance, loveEnergy, x]
```

Грошовий канал:

```text
[x, moneyEnergy, moneyEntrance]
```

### 7.8. Програма сексуальності

```text
sexPoint1 = q
sexPoint2 = R(e + sexPoint1)
sexualityProgram = [e, sexPoint1, sexPoint2]
```

Стать людини не змінює цю числову трійку.

Перша точка програми сексуальності береться із сили роду `q`, а не з `karmaAxis[0]`. На окремих датах ці значення збігаються, тому для перевірки обов’язково використовується контрольна дата `26.07.1997`.

## 8. Метод, який не використовується

Перший метод школи «Біле Сонце» обчислює внутрішні родові точки через зону комфорту:

```text
inner(C) = R(C + e)
```

Ця формула наведена лише для пояснення можливої різниці між калькуляторами. Вона заборонена для використання в поточній реалізації без створення нової версії стандарту та окремого погодження.

## 9. Контрольні приклади

### 9.1. Дата 24.09.1973

```text
a = 6, b = 9, c = 20, d = 8, e = 7
f = 15, g = 11, y = 10, k = 14
q = R(15 + 11 + 10 + 14) = R(50) = 5
```

| Лінія | Внутрішня точка | Зовнішня точка | Очікувана пара |
| :--- | ---: | ---: | :---: |
| NW | `R(15 + 5) = 20` | `R(15 + 20) = 8` | `[20, 8]` |
| NE | `R(11 + 5) = 16` | `R(11 + 16) = 9` | `[16, 9]` |
| SE | `R(10 + 5) = 15` | `R(10 + 15) = 7` | `[15, 7]` |
| SW | `R(14 + 5) = 19` | `R(14 + 19) = 6` | `[19, 6]` |

### 9.2. Дата 29.06.2008

```text
a = 11, b = 6, c = 10, d = 9, e = 9
f = 17, g = 16, y = 19, k = 20
q = R(17 + 16 + 19 + 20) = R(72) = 9
```

| Лінія | Очікувана пара |
| :--- | :---: |
| NW | `[8, 7]` |
| NE | `[7, 5]` |
| SE | `[10, 11]` |
| SW | `[11, 4]` |

У цьому прикладі `q = e = 9`, тому метод через силу роду випадково дає ті самі родові точки, що й метод через зону комфорту. Ця дата не може самостійно розрізнити дві редакції алгоритму.

### 9.3. Розмежувальна дата 15.06.1984

```text
a = 15, b = 6, c = 22, d = 7, e = 5
f = 21, g = 10, y = 11, k = 22
q = R(21 + 10 + 11 + 22) = R(64) = 10
```

Оскільки `q = 10`, а `e = 5`, два методи дають різні результати. Затверджений результат через силу роду:

| Лінія | Очікувана пара |
| :--- | :---: |
| NW | `[4, 7]` |
| NE | `[20, 3]` |
| SE | `[21, 5]` |
| SW | `[5, 9]` |

### 9.4. Контроль програми сексуальності — 26.07.1997

```text
e = 10
q = 11
sexPoint1 = 11
sexPoint2 = R(10 + 11) = 21
sexualityProgram = [10, 11, 21]
```

На правій горизонталі після центральної точки повинні відображатися `11 → 21`. Значення `20 → 3`, отримані через `karmaAxis[0]`, є помилковими.

## 10. Критерії приймання

Реалізація відповідає цьому стандарту, якщо:

1. усі результати належать діапазону 1–22;
2. однакова дата завжди повертає однакові числові значення;
3. зміна статі не змінює числову матрицю;
4. контрольні дати з розділу 9 повертають зазначені значення;
5. родові точки обчислюються через `ancestralStrength`, а не через `center`;
6. порядок масивів відповідає розділу 7;
7. зміни текстових трактувань не змінюють математичні формули.

## 11. Правила внесення змін

- Будь-яка зміна формули потребує нової версії цього документа.
- Зміна методу родових програм потребує окремого письмового погодження.
- До зміни формул потрібно додати контрольний приклад, де старий і новий результати відрізняються.
- Код не повинен змінюватися лише через відмінність трактувань між школами.
- Робочі нотатки не мають нормативної сили, доки їх не внесено до цього документа.
